# Идеальный AGENTS.md для Lab Vault (Vision by Jules)

Привет, будущий ИИ-агент! Добро пожаловать в репозиторий проекта **Lab Vault** (Секретный менеджер для AI-агентов). Этот файл содержит ключевую информацию и правила, которые помогут тебе работать эффективно, безопасно и не ломать существующий код.

## 1. Стек и зависимости
Этот проект представляет собой HTTP-сервис и Telegram-бота без веб-фронтенда.
- **Основной язык:** Go 1.25.0 (указано в `go.mod`).
- **Ключевые зависимости:**
  - `github.com/go-telegram-bot-api/telegram-bot-api/v5` — для работы с Telegram Bot API.
  - `gopkg.in/yaml.v3` — для парсинга и сохранения конфигурационных файлов.
  - `golang.org/x/crypto/chacha20poly1305` — для обеспечения криптографической защиты (шифрование снапшотов секретов).

*Важное правило:* Никогда не изменяй файлы зависимостей (`go.mod`, `go.sum`) и не добавляй новые библиотеки без явного указания от пользователя.

## 2. Команды верификации
В проекте настроен `Makefile`. После любых изменений исходного кода, прежде чем открывать Pull Request, ты **ОБЯЗАН** запустить следующие команды для верификации:

- **Форматирование кода:** `make fmt`
- **Линтер (go vet / golangci-lint):** `make lint`
- **Сборка всех бинарников:** `make build` (или `make all`)
- **Запуск стандартных тестов:** `make test` (покрытие проекта достаточно высокое, 95+ тестов)
- **Проверка на race conditions:** `make test-race`

Относись к тестам серьезно. При добавлении нового функционала старайся практиковать Test-Driven Development (TDD) или, как минимум, добавляй тесты к своему коду. Помни, что пакеты в `cmd/` (cli, env) на данный момент не имеют тестов (0% покрытия), учитывай это при работе с ними.

## 3. Архитектурные особенности и правила кодинга
- **Интерфейсы:** Репозиторий полностью лишен Web UI. Все взаимодействие происходит через CLI-инструменты, Telegram-бота или минимальный HTTP API (порт 8301).
- **In-memory Store & Encrypted Disk:** Секреты хранятся в памяти (RAM), а на диске сохраняется только зашифрованный (или plain, если без пароля) снапшот `snapshot.enc`.
- **Файл конфигурации:** Основная конфигурация живет в `config.yaml`. Токены ботов, админов и агентов хранятся там или передаются через переменные окружения.
- **Безопасность (Security Agent / Sentinel):** Безопасность — критический аспект этого проекта (смотри `AUDIT_FULL.md`). Никогда не коммить API-ключи, пароли или токены доступа. Если ты выступаешь в роли Security Agent (Sentinel), фокусируйся на устранении конкретной уязвимости. При оформлении PR по безопасности используй заголовок `🛡️ Sentinel: [CRITICAL/HIGH] Fix [vulnerability]` и детально описывай уязвимость, ее влияние и методы проверки в теле PR. Всегда спрашивай разрешения перед изменением логики авторизации, добавлением зависимостей или внесением ломающих изменений!
- **Оптимизация и UX:**
  - Оптимизации (Bolt PR: `⚡ Bolt: [performance improvement]`): всегда комментируй, почему проведена оптимизация, замеряй влияние и описывай его в PR.
  - Улучшения UX (Palette PR: `🎨 Palette: [UX improvement]`): фокусируйся на небольших (<50 строк) изменениях (например, диалоги подтверждения для CLI или TG) без бэкенд-изменений или добавления зависимостей.

## 4. Советы для будущих ИИ-агентов
- **Документация vs Реальность:** Внимательно относись к документации (включая `README.md` и `ARCHITECTURE.md`). Согласно `AUDIT_FULL.md`, в документации могут быть неточности (например, про шифрование `ChaCha20-Poly1305` или несуществующие API-эндпоинты). Всегда проверяй реальное состояние кода как единый источник правды.
- **Монолитность `main.go`:** Основная логика бота и сервера сконцентрирована в `main.go`. Будь осторожен при его редактировании, он довольно объемный (более 900 строк). Изменения там могут затронуть различные части системы.
- **Журналирование:** В зависимости от твоей роли веди журналы:
  - `.jules/bolt.md` — для записей об оптимизациях.
  - `.jules/palette.md` — для записей о UX и accessibility.
  - `.jules/sentinel.md` — для критических уязвимостей, их причин и способов предотвращения.
  Используй формат: `## YYYY-MM-DD - [Title] **Learning:** [Insight] **Action/Prevention:** [Action]`.
- **Политика среды:** Если падают тесты или сборка, сначала разберись в корне проблемы по логам и коду. Не пытайся сразу менять зависимости или окружение!
- **Самопроверка:** Всегда используй утилиты чтения файлов (`read_file`, `cat` и др.) после внесения изменений, чтобы убедиться, что они применились корректно.

Удачного кодинга! Сохраняй спокойствие, проверяй результаты работы и не ломай мастер-ветку!
