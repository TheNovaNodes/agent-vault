# Инструкции для ИИ-агентов (Jules' Vision)

Добро пожаловать в репозиторий Lab Vault! Это руководство содержит ключевую информацию, которая поможет ИИ-агентам эффективно, безопасно и корректно вносить изменения в этот проект.

## 1. Стек и зависимости
Проект Lab Vault представляет собой секретный менеджер и использует следующий стек:
- **Основной язык:** Go (Go 1.25.0)
- **Telegram Bot API:** `github.com/go-telegram-bot-api/telegram-bot-api/v5` (v5.5.1) — интеграция с Telegram для управления.
- **Криптография:** `golang.org/x/crypto/chacha20poly1305` — для шифрования снапшотов.
- **Работа с конфигурацией:** `gopkg.in/yaml.v3` (v3.0.1) — для парсинга YAML.

## 2. Команды верификации
Всегда проверяй свои изменения перед сдачей работы. Используй Makefile, который инкапсулирует основные команды:
- **Запуск всех тестов:** `make test` (Обязательно запускай перед отправкой PR. Покрытие должно оставаться высоким).
- **Сборка бинарников:** `make build` (Сборка `agent-vault`, `agent-vault-env` и `agent-vault-cli`).
- **Линтер:** `make lint` (Запускает `go vet` и опционально `golangci-lint`).
- **Форматирование:** `make fmt` (Запускает `gofmt` и `goimports`, приводи код к единому стилю).

*Важно: Если ты работаешь как Sentinel (безопасность), твои коммиты должны начинаться с `🛡️ Sentinel:`.*

## 3. Архитектурные особенности и правила кодинга
- **Безопасность (In-memory + Sealed Mode):** Секреты живут только в RAM. На диске (`snapshot.enc`) хранятся либо в формате Legacy (зашифрован весь файл с помощью ChaCha20-Poly1305), либо в Sealed mode (значения уже зашифрованы). НИКОГДА не выводи значения секретов (plain text) в логи или консоль.
- **Одноразовые токены (One-time):** Токены для доступа к секретам (`ProjectToken`) хешируются через SHA-256 в конфигурации и отзываются после первого использования. Токены сравниваются через `ConstantTimeCompare` для защиты от timing attack.
- **Экранирование HTML:** Телеграм-бот использует HTML (не MarkdownV2). Всегда экранируй пользовательский ввод во избежание XSS или ошибок парсинга.
- **Мутации конфигурации:** При обновлении `config.yaml` сохранение должно быть атомарным (запись во временный файл, затем переименование).
- **Аудит лог:** Любая операция с секретами или токенами (даже чтение) ДОЛЖНА логироваться в `AuditLogger`.

## 4. Советы для будущих ИИ-агентов
- **Не меняй зависимости без команды:** Не редактируй `go.mod` или архитектуру без явного указания.
- **Не добавляй новые библиотеки:** Постарайся использовать стандартную библиотеку Go, если это возможно, чтобы уменьшить площадь атаки.
- **Изучи Makefile:** В нём описаны все важные таски, включая `make dev` для локального запуска и `make deploy`.
- **Помни про Telegram Bot:** При изменении логики бота не забудь запустить тесты (`bot_test.go`), так как бот реализован через FSM и легко сломать его состояния.
- **Проверяй CI:** При пуше срабатывает Github Actions (`Git Hygiene`), в том числе поиск секретов (`gitleaks`), так что не коммить API-ключи, тестовые пароли или секреты.
- **Журнал знаний:** Если ты Sentinel, веди запись в `.jules/sentinel.md`, если Palette — в `.jules/palette.md`, если Bolt — в `.jules/bolt.md`. Описывай только самые критичные знания и уроки.

*Помни: Наш приоритет — безопасность, консистентность и надежность секретов!*
