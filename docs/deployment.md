# Развертывание Lab Vault

Инфраструктура проекта построена вокруг компиляции Go бинарного файла и его запуска в качестве systemd сервиса (`deploy.sh`).

## Переменные окружения

| Переменная | Назначение |
|---|---|
| `VAULT_PASSWORD` | Мастер-пароль. Используется для генерации ключа шифрования In-Memory Store и ChaCha20-Poly1305 `snapshot.enc`. Без него снапшот не сохраняется. |
| `VAULT_ADMIN_TOKEN` | Токен администратора API (перекрывает значение `admin_token` из `config.yaml`). Используется для аутентификации `X-Vault-Token` заголовков. |
| `VAULT_BOT_TOKEN` | Токен Telegram-бота (перекрывает значение `tg_bot_token` из `config.yaml`). Используется для подключения к Telegram API. |

## Настройка конфигурации (config.yaml)
Скопируйте `config.yaml.example` в `config.yaml`.

```bash
cp config.yaml.example config.yaml
```

Внутри вы можете настроить параметры:
- `listen_addr`: адрес HTTP API (например `127.0.0.1:8301`)
- `token_ttl_hours`: время жизни токенов в часах
- Настройки TLS (опционально)
- Telegram ID администратора `tg_admin_id`

## Сборка и Деплой (systemd)

Проект использует Makefile для удобного управления сборкой.

1. **Сборка бинарных файлов**:
```bash
make build
```
Это соберет сервер `lab-vault`, а также утилиты `lab-vault-env` и `lab-vault-cli`.

2. **Деплой через скрипт**:
Скрипт `deploy.sh` выполняет автоматическую сборку, остановку текущего systemd сервиса `lab-vault`, замену бинарного файла, запуск сервиса и прогон проверок здоровья.
Если `deploy.sh` обнаруживает ошибки после старта, он автоматически совершит откат (rollback) на предыдущий бинарник.

```bash
chmod +x deploy.sh
./deploy.sh
```

## Ручной запуск (Dev Mode)
Для локальной разработки вы можете использовать:
```bash
make dev
```
Он запустит бинарный файл напрямую, используя текущие переменные окружения и `config.yaml`.
