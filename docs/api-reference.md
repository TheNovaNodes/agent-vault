# API Reference

Сервер предоставляет HTTP API для управления секретами, проектами и токенами. Все административные эндпоинты защищены токеном. Потребление секретов использует IP rate limiting.

## Глобальные механизмы

- **Rate Limiting**: Эндпоинт доступа к секретам (`/access/`) защищен In-Memory Rate Limiter'ом. Разрешается не более 10 запросов в минуту с одного IP-адреса.
- **Санитизация и Хеширование**: Токены в URL при потреблении немедленно хешируются по алгоритму SHA-256 (`hashToken`), после чего хеш используется для поиска в In-Memory конфигурации.
- **Аутентификация администратора**: Выполняется через заголовок `X-Vault-Token`, который сравнивается с `admin_token` (используя `subtle.ConstantTimeCompare` для защиты от time-based атак).

## Публичные эндпоинты

### `GET /health`
Проверка состояния сервера.

- **Ответ (200 OK):**
  ```json
  {
    "status": "ok",
    "secrets": 5,
    "uptime": "10h30m5s"
  }
  ```

### `GET /access/{token}`
Одноразовое получение секрета (или секретов проекта) по токену.

- **Rate Limiting:** 10 req/min/IP.
- **Ответ (Секрет):**
  ```json
  {
    "name": "api_key",
    "value": "secret_value_here",
    "updated_at": "2023-10-25T15:04:05Z"
  }
  ```
- **Коды ошибок:**
  - `400 Bad Request`: Токен не передан
  - `429 Too Many Requests`: Превышен лимит запросов для IP
  - `403 Forbidden`: Неверный, истекший или отозванный токен
  - `404 Not Found`: Секрет не найден в хранилище

## Административные эндпоинты

Все эндпоинты ниже требуют заголовка `X-Vault-Token` с актуальным токеном администратора.

### Секреты

| Метод | Путь | Описание |
|---|---|---|
| `GET` | `/secrets` | Получение списка всех секретов |
| `POST` | `/secrets` | Создание или обновление секрета. Тело: `{"name": "...", "value": "..."}` |
| `DELETE` | `/secrets` | Удаление **всех** секретов из хранилища |
| `GET` | `/secret/{name}` | Получение информации о конкретном секрете по имени |
| `DELETE` | `/secret/{name}` | Удаление конкретного секрета (включая отзыв всех связанных с ним токенов) |
| `GET` | `/export` | Скачивание всех секретов в виде JSON-файла (`vault-export.json`) |

### Проекты

| Метод | Путь | Описание |
|---|---|---|
| `GET` | `/projects` | Получение списка всех проектов |
| `POST` | `/projects` | Создание нового проекта. Тело: `{"id": "...", "name": "...", "secret_ids": ["..."]}` |
| `GET` | `/project/{id}` | Получение информации о конкретном проекте и его секретах |
| `DELETE` | `/project/{id}` | Удаление проекта (включая отзывы токенов проекта) |

### Токены и Аудит

| Метод | Путь | Описание |
|---|---|---|
| `GET` | `/project-tokens/{id}` | Получение списка всех сгенерированных токенов (хешей) для конкретного проекта |
| `POST` | `/project-tokens/{id}` | Генерация нового токена доступа для проекта |
| `PUT` | `/token/{hash}` | Ротация токена: отзывает старый по хешу и возвращает новый с тем же сроком действия для того же секрета/проекта |
| `DELETE`| `/token/{hash}` | Отзыв токена по его SHA-256 хешу |
| `GET` | `/audit` | Получение списка последних событий из ring-buffer аудит-лога (создание, удаление, потребление токенов) |
